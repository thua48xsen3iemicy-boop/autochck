# Лабораторная: управление узлами по SSH из консоли

## Что нужно сделать

В лабе есть ваша рабочая станция **WS**, маршрутизатор **ROUTER** и десять
Linux-узлов во внутренней сети за ROUTER. Узлы нужно настроить, **не заходя
на них руками**: все действия выполняются командами с WS по SSH через ROUTER
(ProxyJump), циклами по всем узлам сразу.

Правила:

- работаем только с WS и только по SSH;
- не заходим на узлы интерактивно (`ssh node11` без команды): каждое действие
  — команда, которая сразу выполняется на всех узлах;
- каждый блок команд в конце печатает `[OK]` или `[FAIL]` по каждому узлу;
- блок должен спокойно переживать повторный запуск: запустили второй раз —
  ничего не сломалось и не задвоилось.

Логины и пароли для первого входа указаны в описании лабы.

---

## Шаг 1. Найти ROUTER

Внешний адрес ROUTER находится в вашей сети, в диапазоне от `x.x.x.10` до
`x.x.x.20`, где `x.x.x` — первые три числа адреса WS. Какой именно, заранее
неизвестно. Найдём его одной строкой: по очереди пропингуем эти адреса.

```sh
p=$(hostname -I | cut -d. -f1-3); for i in $(seq 10 20); do ping -c1 -W1 $p.$i >/dev/null && echo "$p.$i отвечает"; done
```

Если в списке оказался адрес самой WS, не путайте: ROUTER — другой. Если
не ответил никто, ROUTER ещё загружается: подождите минуту и запустите
строку снова (стрелка вверх, Enter).

### Разбор по кусочкам

Эта строка — несколько простых команд, соединённых вместе. Научиться
собирать такие строки и есть главная цель лабы.

| Кусочек | Что делает |
|---|---|
| `hostname -I` | печатает IP-адреса WS, например `10.1.5.7` |
| `\| cut -d. -f1-3` | `\|` передаёт вывод следующей команде; `cut` режет адрес по точкам и оставляет первые три части: `10.1.5` |
| `p=$( ... )` | `$( ... )` выполняет команду и подставляет её вывод: в переменной `p` теперь `10.1.5` |
| `;` | разделяет команды в одной строке: «сначала это, потом то» |
| `for i in $(seq 10 20); do ... done` | цикл: `seq 10 20` выдаёт числа 10, 11 … 20, и для каждого выполняется то, что между `do` и `done` |
| `ping -c1 -W1 $p.$i` | один пинг (`-c1`), ждать ответа не больше секунды (`-W1`); `$p.$i` превращается в `10.1.5.10`, `10.1.5.11` … |
| `>/dev/null` | прячет вывод ping, чтобы не мешал |
| `&& echo "... отвечает"` | `echo` выполнится, **только если** ping завершился успешно (код возврата 0) |

Запишите найденный адрес: дальше он понадобится в конфиге.

## Шаг 2. Ключ и вход на ROUTER

Создайте ключ, если его ещё нет (на все вопросы — Enter):

```sh
[ -f ~/.ssh/id_ed25519 ] || ssh-keygen -t ed25519 -N "" -f ~/.ssh/id_ed25519
```

Опишите ROUTER в `~/.ssh/config`. Подставьте свой адрес и логин:

```
Host router
    HostName <адрес из шага 1>
    User <логин для ROUTER>
    IdentityFile ~/.ssh/id_ed25519
```

Положите ключ на ROUTER. Пароль спросят один раз, больше не будут:

```sh
ssh-copy-id router
```

Проверьте: команда должна выполниться без пароля.

```sh
ssh router hostname; echo "код возврата: $?"
```

### Код возврата `$?`

Каждая команда, завершаясь, сообщает число: `0` — всё хорошо, другое число —
ошибка. Это число лежит в `$?`, но только до следующей команды: следующая,
даже `echo`, его перезапишет.

`ssh` возвращает код команды, выполненной на удалённой машине. Особый код
`255` значит, что не сработал сам ssh: узел недоступен, ключ не подошёл,
ошибка в конфиге.

## Шаг 3. Найти узлы во внутренней сети

Узнайте внутренний адрес ROUTER:

```sh
ssh router 'ip -4 -o addr show scope global'
```

Один из адресов — внешний (из шага 1), второй — внутренний, например
`192.168.37.1/24`. Узлы находятся в той же внутренней сети.

Теперь пинг из шага 1 нужно запустить **на ROUTER**: с WS внутреннюю сеть
не видно. Что поменялось:

1. `me` — внутренний адрес ROUTER (впишите его сами), он пропускается;
2. диапазон — вся сеть, `seq 1 254`;
3. `&` после команды запускает пинги в фоне, одновременно, а `wait` ждёт,
   пока они закончатся: иначе 254 адреса по секунде — это четыре минуты;
4. печатается только адрес, без слов: этот вывод мы сохраним в файл и будем
   использовать дальше.

Чтобы отправить на ROUTER несколько строк сразу, используем **heredoc**:
всё между `<<'EOF'` и `EOF` уходит на ROUTER как скрипт.

```sh
ssh router 'bash -s' > nodes.txt <<'EOF'
me=192.168.37.1          # <- ваш внутренний адрес ROUTER
p=$(echo $me | cut -d. -f1-3)
for i in $(seq 1 254); do
  [ "$p.$i" = "$me" ] && continue
  ping -c1 -W1 $p.$i >/dev/null && echo $p.$i &
done
wait
EOF
sort -t. -k4 -n nodes.txt -o nodes.txt
cat nodes.txt; echo "найдено узлов: $(wc -l < nodes.txt)"
```

Должно найтись 10 адресов.

### Почему `'EOF'` в кавычках

- `<<'EOF'` — текст уходит на ROUTER как есть, и `$p`, `$i` подставляются
  **там**. Это нам и нужно.
- `<<EOF` без кавычек — bash подставил бы переменные **у вас на WS** ещё до
  отправки, и на ROUTER ушли бы пустые значения.

Ровно так же работают кавычки у самой команды ssh:

```sh
ssh router "echo $(hostname)"   # выведет имя WS: $(...) подставилось до отправки
ssh router 'echo $(hostname)'   # выведет имя ROUTER: подставилось уже там
```

Проверить, что именно уйдёт на удалённую машину, можно, заменив `ssh router`
на `echo`.

## Шаг 4. Описать узлы в `~/.ssh/config`

Общие настройки пишем один раз на группу. Все узлы ходят через ROUTER:

```
Host node*
    User <логин для узлов>
    ProxyJump router
    IdentityFile ~/.ssh/id_ed25519
    StrictHostKeyChecking accept-new
```

`StrictHostKeyChecking accept-new` — при первом подключении ssh сам
запомнит ключ узла и не будет на каждом из десяти узлов спрашивать
«Are you sure you want to continue connecting?». Если ключ уже знакомого
узла вдруг поменяется, ssh по-прежнему откажет в подключении.

Блоки самих узлов не набираем руками, а **генерируем** из `nodes.txt`. Имя
узла — `node` плюс последнее число адреса: `192.168.37.11` → `node11`.

```sh
for ip in $(cat nodes.txt); do
  printf 'Host node%s\n    HostName %s\n' "$(echo $ip | cut -d. -f4)" "$ip"
done >> ~/.ssh/config
tail -n 20 ~/.ssh/config
```

Теперь получим список узлов прямо из конфига. Конфиг — единственное место,
где описана ваша инфраструктура:

```sh
HOSTS=$(awk '/^Host node[0-9]+$/ {print $2}' ~/.ssh/config); echo $HOSTS
```

Переменная живёт только в текущем терминале. Открыли новый — выполните эту
строку снова.

Посмотреть, какие настройки ssh в итоге применит к узлу:

```sh
ssh -G node11 | grep -E '^(hostname|user|proxyjump) '
```

## Шаг 5. Разложить ключи на все узлы

`ssh-copy-id` читает тот же конфиг, поэтому сам идёт через ROUTER. Пароль
спросят по разу на каждый узел:

```sh
for h in $HOSTS; do
  ssh-copy-id $h && echo "[OK]   $h" || echo "[FAIL] $h (код $?)"
done
```

Проверяем, что теперь всё работает без пароля, и учимся различать ошибки:

```sh
for h in $HOSTS; do
  ssh -o BatchMode=yes $h true
  rc=$?
  case $rc in
    0)   echo "[OK]   $h" ;;
    255) echo "[SSH]  $h — не подключился (сеть, ключ или конфиг)" ;;
    *)   echo "[FAIL] $h — код $rc" ;;
  esac
done
```

`BatchMode=yes` запрещает ssh спрашивать пароль: если ключ не разложен, вы
увидите ошибку, а не приглашение ввести пароль.

## Шаг 6. Запретить вход по паролю на узлах

Теперь, когда везде стоят ключи, пароль больше не нужен. Отключите его
одним циклом:

```sh
for h in $HOSTS; do
  ssh $h "sed -i 's/^#*PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config && (systemctl reload ssh || systemctl reload sshd)" \
    && echo "[OK]   $h" || echo "[FAIL] $h (код $?)"
done
```

Проверка: попытка войти без ключа должна закончиться отказом
`Permission denied (publickey)`.

```sh
ssh -o PubkeyAuthentication=no -o BatchMode=yes node11 true
```

## Шаг 7. Хостнеймы

На каждом узле лежит файл `/etc/lab-role`, например:

```
role=db
idx=2
```

Хостнейм узла должен стать `<role><idx>`, в этом примере `db2`. У каждого
узла и у каждого студента значения свои, поэтому список имён заранее не
выписать: имя узел должен прочитать сам из своего файла.

```sh
for h in $HOSTS; do
ssh $h 'bash -s' <<'EOF'
. /etc/lab-role
hostnamectl set-hostname "$role$idx"
EOF
  rc=$?
  [ $rc -eq 0 ] && echo "[OK]   $h -> $(ssh $h hostname)" || echo "[FAIL] $h (код $rc)"
done
```

`. /etc/lab-role` выполняет файл как скрипт, и строки `role=db`, `idx=2`
становятся переменными. Кавычки у `'EOF'` нужны, чтобы `$role$idx`
подставились на узле, а не у вас.

## Шаг 8. Единый `/etc/hosts` на всех узлах

На всех десяти узлах должен оказаться один и тот же файл `/etc/hosts`:
`localhost` и все узлы с их **новыми** именами. Набирать его руками нельзя:
имена у вас свои. Собираем его из конфига и с самих узлов:

```sh
{
  echo "127.0.0.1   localhost"
  for h in $HOSTS; do
    echo "$(ssh -G $h | awk '/^hostname /{print $2}')   $(ssh $h hostname)"
  done
} > hosts.lab
cat hosts.lab
```

Адрес берётся из конфига (`ssh -G`), имя — с самого узла (`ssh $h hostname`).

Раскладываем файл: он уходит на узел через стандартный ввод (`<`) и
записывается целиком.

```sh
for h in $HOSTS; do
  ssh $h 'cat > /etc/hosts' < hosts.lab && echo "[OK]   $h" || echo "[FAIL] $h (код $?)"
done
```

Почему `>`, а не `>>`: `>>` дописывает в конец, и каждый повторный запуск
добавил бы ещё одну копию списка. `>` перезаписывает файл целиком, поэтому
блок можно запускать сколько угодно раз.

Проверка: у одинаковых файлов одинаковая контрольная сумма, поэтому все
десять строк должны показать одно и то же число.

```sh
for h in $HOSTS; do echo "$h $(ssh $h md5sum /etc/hosts | cut -d' ' -f1)"; done
```

## Шпаргалка

| Что | Пример | Смысл |
|---|---|---|
| Код возврата | `echo $?` | `0` — успех, остальное — ошибка; читать сразу после команды |
| И / иначе | `cmd && echo OK \|\| echo FAIL` | правая часть `&&` — при успехе, `\|\|` — при ошибке |
| Подстановка вывода | `n=$(hostname)` | выполнить команду и подставить её вывод |
| Цикл | `for h in $HOSTS; do ...; done` | повторить для каждого элемента |
| Последовательность | `seq 10 20` | числа от 10 до 20 |
| Двойные кавычки | `ssh h "echo $X"` | `$X` подставляется **у вас** |
| Одинарные кавычки | `ssh h 'echo $X'` | `$X` подставляется **на узле** |
| Heredoc | `ssh h 'bash -s' <<'EOF' ... EOF` | отправить на узел несколько строк как скрипт |
| Файл на узел | `ssh h 'cat > /path' < file` | записать локальный файл на узел |
| Параллельно | `cmd & ... wait` | запустить в фоне и дождаться всех |
| Настройки хоста | `ssh -G node11` | что ssh возьмёт из конфига для узла |
| Без пароля | `ssh -o BatchMode=yes h cmd` | ошибка вместо вопроса о пароле |
| Код 255 у ssh | | не удалось подключиться: сеть, ключ, конфиг |
