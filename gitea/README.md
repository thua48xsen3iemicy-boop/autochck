# Gitea для лабы с git

Здесь общий контейнер Gitea на всю группу. Вариант, где у каждого студента своя Gitea на узле `git` внутри лабы, лежит в [`node/`](node/README.md).

Контейнер Gitea 1.24.6 с готовой настройкой под лабу:
- шаблон `course/portals` (четыре портала и конфиги nginx) открыт всем на чтение, писать в него студенты не могут;
- у каждого студента учётка со случайным паролем и пустой приватный репозиторий `<логин>/portals`;
- вход только по паролю через HTTP: SSH, регистрация и почта выключены. Создавать другие репозитории и организации студенты не могут.

## Запуск

1. В `docker-compose.yml` укажите адрес, по которому Gitea видна с узлов лабы (`ROOT_URL`, `DOMAIN`), и число студентов (`LAB_STUDENTS`).
2. Поднимите контейнер и создайте всё нужное:
   ```
   docker compose up -d --build
   docker exec gitea-lab init-lab
   ```

Результат появится в `data/lab/` на хосте:

| Файл | Что в нём |
|---|---|
| `accounts.txt` | логин, пароль и адрес репозитория каждого студента, раздать студентам |
| `admin.txt` | логин и пароль админа `labadmin` |
| `token.txt` | токен админа для автопроверки (API Gitea) |

## Свои логины вместо student01..student30

Положите в `data/lab/students.list` по логину в строке. Строки после `#` считаются комментариями. Затем снова запустите `init-lab`. Лучше брать те же логины, что в PNET.

`accounts.txt` всегда соответствует текущему списку студентов. Учётки, которые есть в Gitea, но не попали в список, скрипт не удаляет.

## Повторный запуск и смена пароля

`init-lab` можно запускать сколько угодно раз. То, что уже создано, он не трогает, а новых студентов из списка дописывает.

Новый пароль одному или нескольким студентам:
```
docker exec gitea-lab init-lab --reset student05 student12
```

## Как работает студент

```
git clone http://<адрес>:3000/course/portals.git
cd portals
git remote rename origin upstream
git remote add origin http://<адрес>:3000/student01/portals.git
git push -u origin main          # git спросит логин и пароль
```

Попытка сделать `push` в шаблон получит отказ `User permission denied for writing`.

## Начать заново

```
docker compose down
rm -rf data
```
После этого снова `up` и `init-lab`. Пароли будут новые.

## Состав

- `Dockerfile` — образ на основе `gitea/gitea:1.24.6` с настройками по умолчанию;
- `setup/init-lab.sh` — скрипт `init-lab`;
- `setup/entrypoint.sh` — генерирует `SECRET_KEY` при первом запуске;
- `setup/portals/` — содержимое шаблона. Оно заливается тремя коммитами, чтобы у шаблона была история.
