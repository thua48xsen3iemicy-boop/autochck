# GIT1: сеть, Git и SSH

Файл лабы: `GIT1.unl`. Модуль: `/pnet/checks/GIT1.py`.
В description добавить `autocheck:on prepare:on`.
Имена узлов в топологии: `ROUTER`, `Git1`, `Git2`, `Git3`.
Коммутатор соединяет ens4 роутера и ens3 клиентов; настройка коммутатора
не входит в подготовку.

| Узел | Интерфейс | Адрес | Шлюз |
| --- | --- | --- | --- |
| ROUTER | ens3 | DHCP | DHCP |
| ROUTER | ens4 | 10.10.1.254/24 | — |
| Git1 | ens3 | 10.10.1.1/24 | 10.10.1.254 |
| Git2 | ens3 | 10.10.1.2/24 | 10.10.1.254 |
| Git3 | ens3 | 10.10.1.3/24 | 10.10.1.254 |

## Преднастрой

На запущенных Debian с ifupdown подготовка применяет только IP-адреса
и шлюзы. На ROUTER также включает постоянный
IPv4 forwarding и nftables masquerade для 10.10.1.0/24 через ens3.
`/etc/network/interfaces` заменяется, резервная копия —
`/etc/network/interfaces.git1-old`, лог — `/var/log/git1-prep.log`.
На ROUTER ruleset заменяется учебной конфигурацией с разрешённым forwarding;
исходный `/etc/nftables.conf` сохраняется как `/etc/nftables.conf.git1-old`.
Повторная подготовка не меняет узлы, у которых сохранилась метка подготовки.

## Задание студенту

1. Задать всем четырём узлам hostname по имени узла в топологии и сохранить
   его после перезагрузки.
2. Установить пакет `git` на Git1, Git2, Git3.
3. На ROUTER под root создать отдельный общий ключ для работы с Git-узлами,
   например `/root/.ssh/git1_lab`, без парольной фразы.
4. Настроить SSH-клиент root на ROUTER: имена Git1, Git2, Git3 должны
   разрешаться в адреса из таблицы, использовать пользователя root и
   созданный ключ через `IdentityFile`. Можно использовать
   `/root/.ssh/config`, системный `/etc/ssh/ssh_config` и `Include`.
5. Добавить публичную часть этого ключа в `/root/.ssh/authorized_keys`
   каждого из Git1, Git2, Git3.
6. Выполнить все пять заданий из [учебной инструкции](git1-student.md)
   на каждом из Git1, Git2, Git3: `/root/task-01` … `/root/task-05`.

Пример записи для одного узла (аналогично для остальных):

```sshconfig
Host Git1
    HostName 10.10.1.1
    User root
    IdentityFile /root/.ssh/git1_lab
```

Преднастрой не настраивает DNS, не устанавливает Git, не меняет hostname,
не создаёт SSH-конфиг, не генерирует и не распространяет ключи. Для работы
студента по SSH используются уже имеющиеся на образах SSH-службы и доступы.

## Автопроверка

| Пункт | Баллы |
| --- | --- |
| Текущее и сохранённое имя каждого узла | 4 |
| Пакет git установлен, git --version работает на клиентах | 3 |
| Действующие HostName и User root для клиентов на ROUTER | 3 |
| Общий отдельный приватный ключ в IdentityFile для всех клиентов | 1 |
| Соответствующий публичный ключ в authorized_keys root клиентов | 3 |
| Задание 1: исходная main, ветки, чистота, updateInstead на трёх узлах | 15 |
| Задание 2: исходная main, ветки, чистота, updateInstead на трёх узлах | 15 |
| Задание 3: один коммит с изменением MAINTAINER на трёх узлах | 15 |
| Задание 4: перенос коммита из task-03 на трёх узлах | 15 |
| Задание 5: исходные main и training, выбрана training на трёх узлах | 15 |
| Задание 3: одинаковый корректный коммит на Git1–Git3 | 1 |
| Задание 4: совпадение main во всех шести task-03/task-04 | 1 |

Итого 91 балл без дополнительных штрафов; встроенные проверки исключены.
Для hostname регистр не важен, у FQDN сравнивается часть до первой точки.
Стандартные ключи `/root/.ssh/id_rsa`, `id_ed25519` и аналогичные не
засчитываются как отдельный ключ лабы. Публичный ключ выводится из приватного
через `ssh-keygen -y`: один файл `.pub` без соответствующего приватного ключа
на ROUTER не засчитывается. Приватный ключ в отчёт не передаётся.
Проверяется наличие ключа на клиентах; действующий вход по SSH, права файлов
и политика sshd отдельными пунктами не оцениваются.


Каждое задание даёт до 5 баллов на каждом клиенте: по баллу за рабочий
Git-репозиторий по нужному пути, правильные локальные ветки/выбранную ветку
и отсутствие тегов, правильную версию, чистые файлы и индекс,
локальную настройку `receive.denyCurrentBranch=updateInstead`.
Ошибки показываются с именем узла и номером задания. Недоступный узел
не получает баллов за свои задания; результаты остальных сохраняются.

Версии проверяются без bundle и без сети:

- Задания 1–2: `main` точно равна исходной main, без новых коммитов.
- Задание 3: ровно один обычный коммит с родителем — исходной main;
  дерево файлов точно соответствует единственной замене MAINTAINER.
  Хеш дерева учитывает содержимое, имена и режимы файлов. Подпись автора
  и сообщение коммита произвольные.
- Задание 4: main равна корректной main задания 3 на том же узле.
  Дополнительно сравниваются все шесть task-03/task-04. Хеш не сохраняется
  между проверками: сравнивается текущее состояние всех репозиториев.
- Задание 5: локальные main и training точно равны исходным веткам,
  выбрана training. Одной ссылки `origin/training` здесь недостаточно.

В заданиях 1–4 допускается только локальная main; в задании 5 — main и training.
Remote-tracking ссылки `origin/*` не считаются дополнительными локальными
ветками. В каждом задании теги запрещены. Чистота проверяется через
`status --porcelain --untracked-files=all`, включая неотслеживаемые файлы;
игнорируемые файлы Git не считает изменениями.

Исходные коммиты: root `55cf9bdd2fe5d47038e292562bbd5253508c14d7`,
main `c0f0169009e0c413ea9d4906af993baca1dac3e5`,
training `cb80c4930676a85df1e2591e6bc70c44cec7028f`.
Ожидаемое дерево задания 3: `796f8df8a5d529ed1f79726eca77b345da468943`.
Проверка только читает репозитории, не создаёт коммиты, не переключает
ветки, не выполняет fetch/push и не меняет настройки. Предконфиг сохранён.
Проверка не доказывает, какие команды студент выполнял на xrdp: оценивается
конечное состояние репозиториев.
